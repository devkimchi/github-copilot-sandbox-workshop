# 배포 전 검증과 공개 준비 체크리스트

워크숍 자료를 검토하고 리허설한 뒤 공개하기 위한 작업 순서다. 각 항목은 실제로 확인한 뒤 완료 표시하고, 실행 결과와 근거는 민감 정보를 제외해 기록한다. 실패하거나 진행하지 않은 항목은 완료로 표시하지 않는다.

상세 검증 기준과 버전표는 [강사용 운영 가이드](instructor-guide.md)를 따른다. 정적 검사 통과만으로 실습 리허설이 완료된 것은 아니다.

## 1. 공개 범위와 운영 조건

- [x] 인계 아카이브 `sandbox-workshop-session-archive.md`를 `.gitignore`에 추가한다.
- [x] 로컬 윤문 산출물 `_workspace/`를 `.gitignore`에 추가하고 Git 추적 대상에서 제외한다.
- [x] 참가자 템플릿에 포함할 `AGENTS.md` 지침을 작성한다.
- [x] 공개할 파일 목록을 확인하고 인계 아카이브, 개인 기록, 비밀과 불필요한 생성물이 포함되지 않도록 한다.
- [x] 지원할 참가자 OS와 환경, 선택적 Windows VM 사용 범위를 문서에 명시한다. (개인 PC는 Windows, macOS, Linux를 대상으로 하고 Windows VM은 선택 경로로 둔다. Codespaces, 일반 VDI와 회사 PC는 지원 범위에서 제외한다.)
- [x] 참가자 인증 방식과 Copilot 라이선스, 조직 정책 준수 안내를 문서화한다. (`docs/00-prerequisites.md`에서 개인 Copilot 라이선스와 짧은 만료 기간의 fine-grained PAT 사용, 조직 정책 우회를 금지하는 원칙을 안내한다.)
- [x] 실제 참가자의 Copilot 라이선스와 조직 정책이 실습을 허용하는지 확인한다. (사용자 확인, 2026-11-25)
- [x] 개인 Azure 구독 사용과 참가자별 자원·자격 증명 준비 절차를 문서화한다. (`docs/00-prerequisites.md`에 개인 구독, 참가자별 sandbox group, RBAC, credential 준비 절차를 안내한다.)
- [ ] 실제 참가자의 Azure 구독, 권한, quota, 비용 승인과 자격 증명을 리허설 전에 확인한다.
- [ ] 워크숍 자료의 라이선스 종류와 권리자를 확정하고 `LICENSE`와 안내를 갱신한다.
- [ ] Tailspin, Docker, agent-box 등 제3자 자료의 라이선스와 출처·고지 및 공개 가능 범위를 확인한다.

## 2. 리허설 준비와 승인

- [ ] 각 지원 OS와 환경의 도구 버전, 설치 방법, CPU 아키텍처와 요구 사항을 확인한다.
- [ ] Copilot CLI, Node, Git, `sbx`, `aca`와 workload/mixin의 후보 버전 및 digest를 정한다.
- [ ] Playwright 버전·mixin 인자와 브라우저 다운로드 경로를 확인한다.
- [ ] ACA 지역, 이미지 revision, tier, quota, 예상 비용과 예산 한도를 확인한다.
- [ ] 모델, npm, GitHub archive 및 Playwright에 필요한 네트워크 호스트를 확인한다.
- [ ] 리허설의 다운로드, 도구 실행, 모델 호출과 Azure 자원 사용 범위 및 비용을 별도로 승인받는다.
- [ ] Windows VM을 검증할 경우 이미지, SKU, 지역, Bastion, 라이선스, 도구 checksum과 비용을 확인하고 별도로 배포 승인을 받는다. 사용하지 않을 경우 선택 경로로 남긴다.

## 3. 실습 리허설

- [ ] 각 지원 OS와 ACA에서 앱 추출 결과의 파일 목록·내용, clean 기준 커밋, `baseline` 태그와 remote 부재를 확인한다.
- [ ] 추출 앱과 템플릿에서 의도하지 않은 agent, MCP, Copilot 지침과 승인된 구문 검사 외의 workflow가 로드되거나 포함되지 않는지 확인한다.
- [ ] 템플릿의 `AGENTS.md`가 각 실습 환경에서 로드되는지와 결과에 미치는 영향을 확인하고 기록한다.
- [ ] 각 지원 OS에서 동일 명령의 Copilot sandbox OFF/ON, 외부 canary, Denied 우선순위와 최소 권한을 비교한다.
- [ ] host sandbox ON, Docker v3 기본 및 Playwright 조합, ACA에서 `npm ci`, unit, build, E2E의 결과를 각각 기록한다.
- [ ] Docker Direct/Clone 공유 방식, 정책·네트워크 차단과 결과 회수 절차를 확인한다.
- [ ] Playwright mixin의 `1.65.0` 정합, 인자와 추가 브라우저 다운로드 여부를 확인한다.
- [ ] 180분 확장용 mixin의 source build, 적용과 접근 범위를 검증한다.
- [ ] ACA의 인증·권한과 egress, 실행 중지·재개 후 동일 파일 상태 및 결과 회수를 확인한다.
- [ ] sandbox ON에서 부모 실습 문서와 `checkpoints/` 접근 여부를 확인한다. 패치가 읽히면 강사 시점 배포로 운영 방식을 바꾼다.
- [ ] 선택한 Windows VM 경로에서 배포, 도구 설치, 재부팅, 모듈별 실행과 정리를 확인한다. Trusted Launch를 낮추지 않고 Docker 중첩 가상화를 검증하며 실패하면 개인 PC 경로를 안내한다.
- [ ] 현장과 같은 네트워크에서 전체 시간표를 확인하고 cleanup 후 잔존 자원과 비용을 확인한다.
